## 3. 에이전트 설계: 사람이 확인하는 단계

중요한 결정에는 사람이 확인하는 단계를 두라는 조언에 맞춰 아래를 지켜요.

| 결정 | 확인 방식 | 상태 |
|---|---|---|
| 고객 정보 추출 | 에이전트가 뽑은 값마다 "내가 말한 값/물어볼 값/기본값/계산한 값"을 표시하고, 시작 질문 카드에서 고객이 값을 확인·수정해요. 말하지 않은 값은 '아직 몰라요 · 물어볼 값'으로 두고, 금액 칸은 빈 칸으로 시작해요(13e). | ✅ |
| 후보 집 고르기 | 에이전트는 정렬만 하고 추천 순위는 매기지 않아요. 고객이 2~3곳을 직접 골라요. | ✅ |
| 시뮬레이션 실행 | "이 집들로 살아 보기"를 고객이 눌러야 실행돼요. | ✅ |
| 전세 위험·지원 제도 | 판정하지 않고 확인할 항목과 출처를 보여 줘요. | ✅ |
| 판단 가드 | 모델 판단이 규칙과 어긋나면 규칙값으로 되돌리고 그 사실을 기록해요. | ✅ |

결정(사용자, 10-30):
- 집 점수는 **내 기준 점수**로 보여 줘요. 고객이 정한 비중(정하기 전에는 "모두 보통")으로 계산한 주관적인 0~100 점수이고, 결과 화면 맨 앞에 둬도 돼요. 비중과 계산식은 한 번 누르면 보여요. 치안 건수는 합산하지 않아요. "추천 집", "이긴 집" 같은 말은 쓰지 않아요. 지금 있는 "한 숫자로 보기"(9a, `web/src/priorities.js`)를 앞으로 꺼내는 일이에요.
- 시나리오가 없는 가족 유형(재택근무자·3세대·반려견)은 마감까지 "미지원"으로 둬요(16a 지시서).
- 데모에서 엘리베이터 대기·층간소음 장면은 빼요. 음성 입력, SAM 3.1 측정, Spark Open 가족 에이전트, 실제 거주자 비교, 새 생활 사건, 나머지 가족 유형은 README에 "준비 중"으로만 적고 지금은 하지 않아요.
