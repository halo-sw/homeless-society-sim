# Ithaca 디자인 시스템 · 랜딩 · 앱 레이아웃 (Stage 28a)

근거: `docs/product.md` 전부, orchestrator의 코드 감사(아래 파일·클래스명 인용).
이 문서가 이후 단계의 정확한 사양이다. 이후 단계는 이 문서대로 구현한다.

## 1. 원칙

1. 첫 화면은 Ithaca가 하는 일을 한 문장으로 말하고, 바로 입력 칸을 준다.
2. 한 화면에는 주요 행동 하나만 있다. (랜딩: 입력 시작 / 대화: 답 뒤 제안 2~3개 / 작업판: 패널당 행동 하나)
3. 오버레이는 정해진 자리(모서리 규칙)에만 둔다. 지도 위에 직접 뜨는 것은 컨트롤 그룹 하나뿐이다.
4. 모든 버튼은 세 가지 중 하나다. 네 번째 생김새는 만들지 않는다.
5. Muse의 일은 항상 행으로 보인다. 숫자는 도구에서만 나온다.
6. 라벨은 문장이다. 잘리는 버튼(`장면 …`)은 버그로 취급한다.

```css
--ds-page: #f6f4ef;      /* 페이지 바탕 (기존 유지) */

--ds-sunken: #ece8df;    /* 입력 칸·움푹한 영역 */
--ds-line: #ddd6c8;      /* hairline 경계선 */
--ds-ink-1: #1d1b18;     /* 본문 (기존 유지) */
--ds-ink-2: #5c564c;     /* 보조 설명 */
--ds-ink-3: #8a8275;     /* 플레이스홀더·캡션 */
--ds-action: #1d1b18;    /* 주요 버튼 채움 (near-black) */
--ds-accent: #2f6fed;    /* 링크·진행 중 표시만 (기존 유지) */
--ds-home-a: #b3541e;    /* A집 (따뜻한 갈색) */
--ds-home-b: #2f6fed;    /* B집 (파랑, accent와 동일값) */
```

### 2.3 서체

- 본문·UI 전부: Pretendard (self-hosted `/fonts/pretendard/`, 현행 유지).
- 표시용(display): Noto Serif KR (Google Fonts 로드). **허용 위치는 랜딩 히어로·섹션 제목과 빈 대화 제목뿐.** 카드·버튼·본문·캡션에는 쓰지 않는다.

```css
--ds-font-sans: "Pretendard", system-ui, sans-serif;
--ds-font-display: "Noto Serif KR", serif;
--ds-t-12: 12px; --ds-t-14: 14px; --ds-t-16: 16px;
--ds-t-20: 20px; --ds-t-24: 24px; --ds-t-28: 28px;
--ds-t-40: 40px;  /* 랜딩 히어로만 */

--ds-lh-tight: 1.25; --ds-lh-body: 1.6; --ds-lh-display: 1.3;
```

본문 16px·1.6, 캡션·태그 12~14px·1.25가 기본이다.

```css
--ds-s-4: 4px; --ds-s-8: 8px; --ds-s-12: 12px; --ds-s-16: 16px;
--ds-s-24: 24px; --ds-s-32: 32px; --ds-s-48: 48px;
```

- 간격은 위 스케일만 쓴다. 기존 `ui.css`의 2·6·10px은 폐지한다(1px hairline만 예외).
- 그림자는 카드에 얇게 하나, 뜬 패널에 하나. 그 외 섀도우 금지(hairline 경계가 기본).
- 브레이크포인트: 480px(휴대폰) / 960px(작업판을 오버레이로 전환).

## 3. 컴포넌트

### 3.1 Button — primary / secondary / ghost, sm / md

- 구조: pill(`--ds-r-pill`), 라벨 한 줄·잘림 금지, 최소 높이 sm 32px / md 44px.
- primary: `--ds-action` 채움 + page색 글자. 화면당 하나. 지금의 검은 `담기`·트레이 `이 집들로 30일 살아 보기`를 이것으로 통일한다.
- secondary: 흰 바탕 + `--ds-line` 테두리. 지금의 흰 외곽선 `지도로`·`새 창으로`가 이것이다.
- ghost: 테두리 없는 텍스트. 지금의 `지도에서 보기`·`3D로 보기 →`가 이것이다. `장면 보기` 잘림은 ghost에 `white-space: nowrap`을 넣어 고친다.
- 쓰지 말 때: 제안·시작 버튼에 secondary를 쓰지 않는다(아래 SuggestionChip 자리). Astryx `ghost ×40`·`secondary ×20` 혼용을 끝내고 이 세 가지로 대체한다.

### 3.2 IconButton

- 32px 정사각, 모서리 8px, 흰 바탕. 아이콘만, 라벨은 툴팁. 패널 닫기 `×`(Astryx IconButton 현행)를 이것으로 통일한다.
- 닫기는 패널 헤더에만 둔다. 지도 위·카드 위에 두지 않는다.

### 3.3 SuggestionChip — 제안은 모두 이 생김새 하나

- 구조: `--ds-sunken` 채움 칩 + `--ds-r-pill` + 14px medium. 아이콘 없음.
- 쓰는 곳: 빈 화면 시작 버튼 3개, 답 끝 제안 2~3개. 지금 빈 화면의 `EMPTY_STARTERS`(`web/src/ui/chat.jsx`)와 회색 제안 칩을 전부 이것으로 바꾼다.
- 쓰지 말 때: 본문 링크·확정 행동(시작·담기)에는 쓰지 않는다.

### 3.4 SourceTag — 출처·추정/가정 표시

- 구조: 12px `--ds-ink-2`, 앞점 `·` 구분, 클릭하면 출처 줄이 펼쳐진다. `추정`·`가정함`은 `--ds-warn`색 같은 태그에 prefix로 붙는다(예: `가정함 · 월세 70만`).
- 지금 `확인한 것 n가지` collapsible 안의 출처 칩들을 이것으로 바꾼다. 출처·기간·단위는 태그 안에 항상 함께 둔다.

### 3.5 HomeDisc — 집 표시 A/B/C

- 구조: 28px 원 + 흰 글자(A·B·C). 후보는 번호 순서대로 이 원으로 구분한다.
- 색: A `--ds-home-a`, B `--ds-home-b`, C부터 `--ds-home-c`. 지도 핀·후보 행·동네 보기 마커가 같은 글자를 쓴다.

### 3.6 Composer — 입력 칸

- 구조: 둥근 박스(`--ds-r-composer`, surface + line) 안의 textarea + 왼쪽 아래 붙이기(`+ 매물 글 붙이기`) + 오른쪽 아래 보내기(원형 primary). 그 아래 한 줄 모델 표시(`Muse · Muse Spark 1.3` 또는 `Muse 연결 안 됨 · 규칙으로 답했어요`).
- 지금 톱바의 파란 `연결됨 · Muse Spark 1.3` 뱃지를 없애고 이 한 줄로 옮긴다.
- 랜딩 히어로와 앱이 같은 Composer를 쓴다. 플레이스홀더: "판교 출근인데 전세 2억 이하로 혼자 살 집 찾아 줘".

### 3.7 MuseWorkLog — Muse가 한 일 기록

- 구조: 답당 하나. 접힌 요약행(`▸ 실거래 확인 · 출근 계산 — 41곳`) + 펼치면 도구별 행(도구 이름·걸린 시간).
- 지금 `확인한 것 n가지` collapsible 행을 이것으로 바꾼다. 도구 호출이 없는 답에는 WorkLog를 달지 않는다.

### 3.8 CandidateRow — 후보 한 줄

- 구조: HomeDisc + 사진 72px + 이름·가격·3줄(출근·월비용·확인할 것) + 담기(ghost→ 담은 뒤 primary 전환 아님, 담은 표시는 Disc 테두리).
- 지금 후보 카드의 6행(사진 + 이름 + 가격 + 3줄)을 이 행으로 통일한다. 행 전체가 아니라 이름·`지도에서 보기` ghost가 진입점이다.

### 3.9 ResultCard + DiaryRow — 살아 본 결과

- 구조: 결과 한 문단 + 근거 줄(`✓ 문장 8개 모두 기록과 대조`) + 비용·출근 미니표 + 일기 행(날짜·한 줄·`그 장면 보기` ghost, 잘림 금지).
- `내 기준 점수`(0~100, 고객 가중치·수식 한 탭 거리)를 카드 맨 위에 둔다. 점수 옆에 `모두 보통` 또는 가중치 요약을 함께 둔다.
- `추천`·우승자 문구는 쓰지 않는다.

### 3.10 MapControls — 지도 컨트롤 한 그룹

- 구조: 오른쪽 아래 세로 그룹 1개. 순서: 확대(+)·축소(−)·맞춤(fit)·레이어. 32px 흰 버튼, 아이콘 + 툴팁 라벨.
- 지금의 흩어진 `.ui-chatmap-zoom`(`ui.css:655-664`, `+`·`−`·텍스트 `맞추기`)을 이 그룹으로 합친다. 텍스트 `맞추기`는 아이콘 버튼 + 툴팁 `전체를 보여줘`가 된다.

### 3.11 모서리 규칙 + PanelHeader

- 왼쪽 위: 제목 알약(지역·집 이름). 오른쪽 위: 범례. 오른쪽 아래: MapControls. 아래 가운데: 아무것도 띄우지 않는다.
- 지금 `.ui-stage-pill`(`ui.css:666-668`)과 범례가 닫기 `×`와 겹치는 문제를 이렇게 푼다: 닫기는 PanelHeader(제목 + `×` IconButton)로 올린다.
- SegmentedToggle: 지도/동네 등 패널 안 전환용. PanelHeader 아래 한 줄, secondary pill 그룹. 휴대폰 `대화/지도` 탭(26m/26p 현행)은 이것으로 통일한다.

## 4. 화면

### 4.1 랜딩 (`/`)

- 내비: `Ithaca` · `기능` · `살아 보기` · `데이터` · `질문` · 검은 `시작하기` pill. 공지 바 한 줄: "지금은 분당·판교 일대부터 천천히 넓혀 가는 중이에요".
- 히어로(중앙, 최대 760px): serif 제목 "어떤 집을 고민 중이세요?" + lede 한 줄 "Muse가 직접 확인하고, 대신 30일 살아 보고, 대화로 알려 줘요." + Composer + 칩 3개(`출근지로 집 찾기` · `본 매물 붙여 넣기` · `예시로 써 보기`) + 커버리지 한 줄 "다루는 지역: 성남시 분당구 일대 · 지도 가격은 국토교통부 실거래 중간값(25.10–26.10)".
- 제품 프레임: 둥근 프레임 안 실제 대화 스크린샷 1장. 아래 세 칼럼: "물어보면 Muse가 고른다 — 기능은 모두 Muse의 도구예요" / "숫자는 세서 말한다 — 시간·거리·돈은 엔진이 계산해요" / "산 것은 네가 정한다 — 비교만 보여주고 고르라 하지 않아요".
- 비교표: 직접 정리 / 일반 챗봇 / Ithaca. 행: "매물 가격을"→(내 기억 / 확률로 지음 / 국토부 실거래 중간값에 대조), "출근 시간을"→(대충 어림 / 노선도 거리 / 걷기+지하철+기다림을 셈), "살아 볼 수 있나"→(불가능 / 불가능 / 30일 시뮬레이션 일기). Ithaca 열만 음영.
- 문제 제기: 소제목 "집 고를 때 진짜 막막한 것들" + 일러스트 2장. "사진 속 집과 동네의 밤은 아무도 안 알려 줘요" / "한 달에 얼마 드는지, 살아 보기 전엔 몰라요".
- 실제 쓰임 2×2: "판교 출근 신입의 첫 자취 — 미금역 7분, 전세 실거래로 좁혀요" / "결혼 앞둔 두 사람의 비교 — 돈·출근·확인할 것을 나란히" / "밤 귀갓길이 걱정될 때 — 기록에서 밤 10시 이후 귀가만 꺼내요" / "부모님께 설명할 때 — 그림 저장·링크 공유 한 번에".
- 동작 순서 4단계: "1. 말로 물어봐요" / "2. Muse가 확인해요(▸ 줄이 남아요)" / "3. 요청하면 지도로·동네로 보여줘요" / "4. 30일 살아 본 일기로 전해요".
- 예시 프롬프트(복사 버튼): "판교 출근, 전세 2억 이하로 찾아 줘" / "분당오벨리스크 동네는 어때?" / "여기랑 천사의도시 비교해 줘" / "이 전세 괜찮아?".
- FAQ(답은 제품 규칙 준수):
  - "가격이 오를까요?" → "오름·내림은 말하지 않아요. 대신 네가 고른 가정(−2/0/+2%씩 매년)으로 나란히 견줘 보여요."
  - "어디가 제일 좋아요?" → "우승자는 없어요. 네 기준 비중으로 정렬한 `내 기준 점수`만 보여주고, 고르는 건 네 몫이에요."
  - "이 전세 안전한가요?" → "안전 판정은 하지 않아요. 보증금 비율 같은 공개 신호, 확인할 것 목록, 모의 손실 시나리오를 드려요."
  - "지원금은 받을 수 있나요?" → "합격 판정은 하지 않아요. 네 조건과 공고 조건을 항목별로 대조해 보여줘요(기준일·공식 링크 포함)."
  - "밤길은 안전한가요?" → "점수는 매기지 않아요. 공식 통계(출처·기간·단위·지역 단위)와 밤 귀갓길 기록을 보여줘요."
  - "일기는 진짜예요?" → "가상 주민(모의) 일기예요. `✓ 문장 8개 모두 기록과 대조`처럼 근거 검사를 통과한 문장만 보여줘요."
- 데이터 출처 줄: "국토교통부 실거래가 / OpenStreetMap / 서울교통공사 혼잡도 / GIS건물통합정보".
- 마지막 CTA: serif 제목 "먼저 한 문장만 물어보세요." + 검은 `대화로 시작하기` pill.

### 4.2 랜딩↔앱 연결

- `/`는 랜딩, 앱은 `/?app=1`. `web/src/chat/urls.js`의 `routeForSearch`는 `/?app=1`을 반환한다.
- 랜딩 Composer 입력·칩·예시 프롬프트 복사는 모두 그 문장을 들고 `/?app=1`로 넘어가 자동 전송한다. 랜딩에서 시작한 대화가 곧 집 고민 대화 1개가 된다.

### 4.3 앱 빈 상태 (새 대화)

- 화면 중앙에 760px 블록을 수직 중앙(아래 8vh 광학 보정)에 둔다: serif 제목 "어떤 집을 고민 중이세요?" + Composer + 칩 3개 + 예시 카드 1행 + 출처 한 줄. 1440px에서도 2000px에서도 이 블록은 중앙 고정, 너비는 760px을 넘지 않는다. 빈틈(见出し 상단·입력칸 하단 사이 600px 공백)은 예시 카드와 출처 줄이 채운다.
- 예시 카드: 위 2×2 중 3개를 가로 3열 미니 카드로. 클릭하면 그 문장이 전송된다.

### 4.4 앱 셸 (너비 > 960px)

- 왼쪽 사이드바 280px: `+ 새 대화` / `최근 대화`(localStorage) / `예시` / 맨 아래 `한국어·English`(톱바의 `English`를 여기로 옮긴다) + `Muse 상태`.
- 가운데 대화 칼럼(최대 760): 헤더는 대화 제목(프로필 요약에서). 스레드는 사용자 말풍선 → Muse 글 → WorkLog 1개 → 카드 순서. 렌치 아이콘은 없앤다(도구는 WorkLog가 보여준다).
- 맨 아래: 제안 칩 2~3개 + Composer(모델 한 줄 포함).
- 오른쪽 작업판 560px: 요청이 있어야 열린다. 닫으면 대화 칼럼이 중앙으로 돌아온다.

### 4.5 작업판 — 지도

- 모서리 규칙 적용. 찜 트레이(`.ui-picks-tray`, `ui.css:670-680`, 지도 아래 중앙 부유)는 폐지한다.
- 찜 목록은 패널 헤더 아래 얇은 strip(집 Disc + 이름 + ×)으로 들어간다. `30일 살아 보기` 시작 primary는 채팅 제안이 1순위이며, 패널 하단 풋터에 같은 primary를 둔다(두 곳 모두 같은 요청을 보낸다).

### 4.6 작업판 — 동네 보기 (클로즈업 3D 대신)

- 첫 장면은 내려다보는 개요(탑다운/비스듬)다. 집을 HomeDisc 마커로 중앙에 찍는다.
- `neighborhood` 도구 결과의 `nearest: [{category_ko, name, minutes, distance_m}]`에 있는 곳만 그린다. 각 곳에 이름 + `걸어서 n분` 라벨과 집까지의 도보 경로선을 함께 그린다. 결과에 없는 공원·가게는 그리지 않는다(자동 투어 카드 폐지, 자동 넘김 없음).
- 집 `lon/lat`가 중심이다. `미금역 3.8분`·`마트 2.3분`처럼 Muse가 말한 곳이 화면 밖에 있으면 버그다.
- 가까이 걷는 3D는 토글로 둔다(SegmentedToggle: `한눈에 보기` / `걸어 보기`). 기본값은 `한눈에 보기`.

### 4.7 휴대폰 (≤ 480px)

- 랜딩은 쌓는다: 히어로 → Composer → 칩 → 제품 프레임 순. 비교표는 행 쌓기로.
- 앱은 현행(26m/26p) 유지: 대화 전체 화면, 상단 `대화/지도` SegmentedToggle. 작업판은 전체 화면 시트로 열린다. Composer 모델 한 줄은 유지한다.
