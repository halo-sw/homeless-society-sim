# OSM 기반 3D 씬 — 도로·숲·나무 렌더링 작업 지시서

Oct 29, 2026 · @Halo

## 1. 목표와 범위

지정한 영역(아파트 단지\~동네 규모)의 **지형, 도로, 숲·녹지, 개별 나무**를 OSM 데이터로 자동 생성해 브라우저에서 60fps로 보여준다. 건물은 이번 범위에서 제외하고, 이후 건물 레이어가 같은 좌표계 위에 얹힐 수 있게 만든다.

- **참고 사례**: [SMASH GACHON](https://hong-iron.github.io/SMASH-GACHON/) — OSM 데이터를 JSON으로 미리 구워 Three.js로 절차 생성하는 구조. 같은 구조를 따른다.
- **입력 파라미터**: 중심 위경도(`lat`, `lon`), 반경 또는 bbox(기본 반경 500m), 지역 이름.
- **산출물**: 데이터 빌드 스크립트 1개, 씬 JSON 1개, 렌더러(HTML + JS) 1개.
- **범위 밖**: 건물, 물리·파괴 연출, 게임 로직, 실사 텍스처.

대상 지역은 아직 정하지 않았다. 첫 테스트 지역은 기존 사례와 비교할 수 있게 가천대 글로벌캠퍼스(37.4529, 127.1314) 반경 500m로 한다.

## 2. 기술 스택과 전제

| 영역 | 사용 기술 | 비고 |
| --- | --- | --- |
| 렌더링 | Three.js 0.160 (ES module, import map) | 참고 사례와 동일 버전 |
| 후처리 | EffectComposer + N8AO + SMAA | 성능 부족 시 AO 끄기 옵션 |
| 하늘·조명 | `Sky.js` + DirectionalLight 1개(그림자) + HemisphereLight |  |
| 카메라 | OrbitControls |  |
| 도로·숲·나무 데이터 | OpenStreetMap, Overpass API | ODbL 라이선스 |
| 지형 데이터 | DEM(고도 격자) | 출처는 3장 |
| 데이터 빌드 | Node.js 또는 Python 스크립트 | 런타임에 API 호출 없음 |
| 호스팅 | 정적 사이트(GitHub Pages 등) |  |

**전제**

- 데이터는 빌드 단계에서 한 번만 받아 JSON으로 굽는다. 브라우저는 Overpass를 직접 호출하지 않는다.
- 모든 좌표는 중심점 기준 **미터 단위 로컨 좌표**로 변환한다. Three.js 축은 x = 동쪽, z = 남쪽(북쪽이 −z), y = 고도.
- 외부 3D 모델(glTF)은 쓰지 않고 나무까지 코드로 만든다. 나중에 교체할 수 있게 나무 생성 함수는 분리해 둔다.

## 3. 데이터 수집

Overpass API 쿼리 1회로 도로·숲·나무를 모두 받고, 지형은 DEM에서 따로 잘라온다. 원본 응답은 `raw/` 폴더에 캐시해 재호출을 막는다.

### 3.1 Overpass 쿼리

```
[out:json][timeout:60];
(
  way["highway"](around:{R},{LAT},{LON});
  way["railway"~"rail|subway|light_rail"](around:{R},{LAT},{LON});
  way["natural"~"wood|scrub|grassland|water"](around:{R},{LAT},{LON});
  way["landuse"~"forest|grass|meadow|park|recreation_ground"](around:{R},{LAT},{LON});
  way["leisure"~"park|garden|pitch"](around:{R},{LAT},{LON});
  relation["natural"="wood"](around:{R},{LAT},{LON});
  relation["landuse"="forest"](around:{R},{LAT},{LON});
  way["waterway"](around:{R},{LAT},{LON});
  node["natural"="tree"](around:{R},{LAT},{LON});
  way["natural"="tree_row"](around:{R},{LAT},{LON});
);
out geom;
```

- `{R}`은 렌더 반경보다 100m 크게 잡는다. 가장자리 도로가 끊기지 않게 하기 위해서다.
- 숲 relation(multipolygon)은 바깥 링(outer)과 구멍(inner)을 구분해 저장한다.
- 산 전체가 하나의 거대한 숲 폴리곤인 경우가 많으므로, 영역 밖으로 나간 폴리곤은 bbox로 잘라낸다(clip).

### 3.2 나무 데이터 보완

한국 OSM에는 개별 나무(`natural=tree`)가 거의 없다. 나무 대부분은 **절차 생성**한다.

| 출처 | 배치 방식 | 밀도 기준 |
| --- | --- | --- |
| `natural=tree` | OSM 좌표 그대로 | — |
| `natural=tree_row` | 선을 따라 일정 간격 | 8m 간격 |
| 숲(`wood`, `forest`) | 폴리곤 내부 Poisson-disk 샘플링 | 최소 간격 5m |
| 공원·정원 | 폴리곤 내부 샘플링 | 최소 간격 12m |
| 가로수 | 주요 도로(`primary`\~`tertiary`) 양쪽, 도로 폭/2 + 2m 바깥 | 10m 간격 |

- 도로, 물, 건물 자리(건물 레이어 추가 시)에 걸리는 나무는 제거한다.
- 난수는 시드 고정(예: 지역 이름 해시). 빌드할 때마다 같은 결과가 나와야 한다.

### 3.3 지형(DEM)

| 출처 | 해상도 | 용도 |
| --- | --- | --- |
| 국토지리정보원 수치표고모델(국토정보플랫폼) | 5m급 | 국내 지역 기본값 |
| Copernicus GLO-30 / SRTM | 30m | 백업, 해외 지역 |
| AWS Terrain Tiles(Terrarium PNG) | 줌 레벨에 따라 다름 | 빠른 프로토타입 |

- 어느 출처든 **2.5m 간격 격자로 재샘플링**해 저장한다(참고 사례와 동일). 반경 500m면 약 400×400 격자.
- 사용할 출처의 라이선스와 다운로드 절차는 착수 전에 확인한다(국토정보플랫폼은 회원 가입·신청이 필요할 수 있음).

## 4. 전처리 파이프라인과 JSON 스키마

빌드 스크립트 `build-scene`은 아래 순서로 돌고 `scene.json` 하나를 내보낸다.

1. **다운로드**: Overpass 응답과 DEM을 `raw/`에 저장(있으면 재사용).
2. **좌표 변환**: 위경도 → 중심점 기준 미터. 반경 1km 이내는 등장방형 근사면 충분하다. `x = (lon − lon0) × 111320 × cos(lat0)`, `z = −(lat − lat0) × 110540`.
3. **클리핑·단순화**: bbox 밖 제거, 선·폴리곤을 Douglas-Peucker 0.5m로 단순화, 좌표는 소수점 1자리로 반올림.
4. **분류**: 태그를 렌더러가 쓰는 짧은 코드로 변환(아래 표).
5. **지형 재샘플링**: 2.5m 격자, 고도는 dm(10cm) 정수로 저장해 용량을 줄인다.
6. **나무 생성**: 3.2의 규칙으로 좌표·크기·수종 생성.
7. **출력**: `scene.json`(목표 크기는 반경 500m 기준 1MB 이하, gzip 전).

### 4.1 scene.json 스키마

```
{
  "meta":    { "name": "가천대", "lat": 37.4529, "lon": 127.1314, "radius": 500 },
  "terrain": { "x0": -500, "z0": -500, "step": 2.5, "nx": 400, "nz": 400, "dm": [301, 300, ...] },
  "roads":   [ { "k": "tertiary", "n": "복정로", "w": 9, "br": 0, "p": [[x, z], ...] } ],
  "lands":   [ { "k": "wood", "r": [ [[x, z], ...], [[x, z], ...] ] } ],
  "water":   [ { "k": "stream", "w": 4, "p": [[x, z], ...] } ],
  "trees":   [ [x, z, scale, species], ... ]
}
```

- `lands[].r`: 첫 번째 링이 바깥, 나머지가 구멍.
- `roads[].br`: 다리(1)/터널(−1)/일반(0). OSM `bridge`, `tunnel`, `layer` 태그에서 얻는다.
- `trees`는 수천 개가 되므로 객체가 아닌 배열로 저장한다. `species`: 0 침엽수, 1 활엽수, 2 관목.

### 4.2 도로 등급별 기본 폭

OSM에 `width`나 `lanes`가 있으면 그 값을 쓰고(`lanes × 3.25m`), 없으면 아래 기본값을 쓴다.

| highway 태그 | 폭(m) | 렌더 순서 |
| --- | --- | --- |
| motorway, trunk | 20 | 1 |
| primary | 16 | 2 |
| secondary | 12 | 3 |
| tertiary | 9 | 4 |
| residential, unclassified | 6 | 5 |
| service(단지 내 도로) | 4 | 6 |
| footway, path, cycleway, steps | 2 | 7 |

## 5. 렌더링 명세

모든 레이어는 지형 높이 함수 `heightAt(x, z)` 하나를 공유한다. 도로·숲·나무는 이 함수로 지면에 붙인다.

### 5.1 지형

- `terrain.dm`으로 PlaneGeometry(nx × nz 정점)를 만들고 y값을 넣는다. `computeVertexNormals()` 필수.
- `heightAt(x, z)`는 격자 4점 bilinear 보간. 범위 밖은 가장자리 값으로 고정.
- 색: 기본 풀밭색 + 경사도가 35° 넘는 면은 흙·암반색으로 섞는다(정점 컬러).
- 영역 밖 경계는 안개(`scene.fog`)로 자연스럽게 사라지게 한다.

### 5.2 도로

- 각 도로 중심선을 폭만큼 좌우로 벌린 **리본 메시**로 만든다. 구간을 2m 간격으로 재샘플링해 지형 굴곡을 따라가게 한다.
- 높이 = `heightAt + 0.05m + 순서 × 0.01m`. 교차로에서 z-fighting이 없어야 한다. `polygonOffset`도 함께 쓴다.
- 다리(`br = 1`)는 양 끝 높이를 선형 보간해 지형 위로 띄우고, 터널(`br = −1`)은 그리지 않는다.
- 등급별 재질 3종: 차도(아스팔트 회색), 보도·산책로(밝은 베이지), 자전거도로(적갈색).
- primary 이상은 중앙선(노란 점선) 텍스처 또는 셀이더 줄무늬를 넣는다. 선택 사항.
- 등급별로 `BufferGeometryUtils.mergeGeometries`로 합쳐 **드로우콜 3\~4개**로 제한한다.

### 5.3 숲·녹지·물

- 폴리곤을 `ShapeGeometry`(구멍 포함)로 삼각화한 뒤, 내부를 4m 간격으로 쪼개 지형 높이를 입힌다. 큰 삼각형 그대로 올리면 산에서 떠서 보인다.
- 대안: 지형 메시에 **마스크 텍스처**(숲/잔디/물 영역을 그린 캔버스)를 입혀 색을 칠하는 방식. 기본은 이 방식을 권장한다. 메시가 늘지 않고 떠 보이는 문제가 없다.
- 색: 숲 진녹, 잔디·공원 연두, 관목지 황녹, 물 파랑(반사는 선택 사항).
- 하천·개울(`waterway`)은 도로와 같은 리본 방식, 지면보다 0.3m 낮게.

### 5.4 나무

- 수종별 `InstancedMesh` 1개씩, 총 3개. 나무 수천 그루를 드로우콜 3개로 그린다.
- 형태(로우폴리, 나무 하나당 200 삼각형 이하):
  - 침엽수: 원뿔 2\~3단 + 원기둥 줄기
  - 활엽수: 찌그러뜨린 Icosahedron 1\~2개 + 줄기
  - 관목: 낮은 반구, 줄기 없음
- 줄기와 잎을 한 지오메트리로 합치고 정점 컬러로 색을 나눌다. 인스턴스별 `setColorAt`으로 초록 톤을 ±8% 흔들어 단조로움을 없앤다.
- 크기 0.7\~1.3배, y축 회전 무작위(시드 고정), 높이 = `heightAt(x, z)`.
- 숲 비율: 침엽 40 : 활엽 50 : 관목 10을 임시 기본값으로 두고 설정으로 바꿀 수 있게 한다.
- 그림자: 나무는 `castShadow`만 켜고, 카메라 150m 밖은 그림자에서 뺀다.

## 6. 성능 기준과 확장

반경 500m 씬은 아래 기준을 만족해야 한다. 측정은 `renderer.info`와 Chrome DevTools Performance 탭으로 한다.

| 항목 | 목표 |
| --- | --- |
| 프레임 | 노트북 60fps, 중급 휴대폰 30fps 이상 |
| 드로우콜 | 30개 이하(후처리 제외) |
| 삼각형 | 150만 개 이하 |
| 초기 로딩 | scene.json 1MB 이하, 첫 화면까지 3초 이내 |
| 나무 | 1만 그루까지 위 기준 유지 |

**모바일 대응**: `devicePixelRatio`를 최대 1.5로 제한, N8AO와 그림자 해상도를 낮추는 ‘저사양 모드’ 스위치를 둔다.

### 6.1 동네·도시 규모로 확장할 때

이번 작업에서 구현하지는 않지만, 구조는 아래를 막지 않게 짠다.

- **타일 분할**: 데이터를 250m × 250m 타일로 나눠 `tiles/{tx}_{tz}.json`으로 저장하고, 카메라 주변 타일만 불러온다. 좌표 변환과 `heightAt`은 타일 경계에서 이어져야 한다.
- **LOD**: 나무는 100m 밖 빌보드(평면 이미지), 300m 밖은 숲 폴리곤 색만. 지형은 멀수록 격자를 성기게.
- **건물 레이어 추가**: 같은 `scene.json`에 `buildings` 배열을 더하고, 층수 데이터는 OSM `building:levels` 없으면 국토부 GIS건물통합정보로 보완한다. 나무 생성 단계에서 건물 바닥면을 피해야 하므로 나무 생성 함수는 제외 영역 목록을 인자로 받는다.

## 7. 작업 단계·산출물·완료 기준

단계마다 화면 캡처 1장과 성능 수치(fps, 드로우콜, 삼각형)를 남기고 다음 단계로 넘어간다.

| 단계 | 작업 | 산출물 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 데이터 수집 스크립트 | `build-scene`, `raw/` 캐시 | 좌표·반경만 바꿔 재실행 가능 |
| 2 | 전처리·JSON 출력 | `scene.json` | 4.1 스키마 일치, 1MB 이하 |
| 3 | 지형 렌더 | 렌더러 기본 틀 | 산·언덕 윤곽이 지도와 일치 |
| 4 | 도로 렌더 | 도로 레이어 | 지면에 붙고 교차로 깜빡임 없음 |
| 5 | 숲·녹지·물 | 표면 레이어 | 떠 보이는 면 없음, 구멍 반영 |
| 6 | 나무 | 나무 레이어 | 도로·물 위 나무 0그루, 시드 고정 |
| 7 | 최적화·모바일 | 저사양 모드 | 6장 성능 기준 충족 |
| 8 | 다른 지역 검증 | 지역 2곳 추가 빌드 | 코드 수정 없이 동작 |

**최종 검수 체크리스트**

- [ ] 카카오맵·네이버지도 위성 화면과 나란히 놓고 도로망·숲 경계가 맞는지 눈으로 확인
- [ ] 도로가 산길에서 지형에 묻히거나 떠 있는 구간 없음
- [ ] 같은 입력으로 두 번 빌드했을 때 `scene.json`이 동일
- [ ] 화면 구석에 OSM 출처 표기

## 8. 리스크와 주의사항

| 리스크 | 대응 |
| --- | --- |
| OSM 숲 폴리곤이 없거나 부정확한 지역 | 산지는 DEM 경사도·고도로 ‘숲 추정 영역’을 만드는 옵션을 둔다 |
| 도로가 급경사에서 지형에 묻힘 | 도로 주변 지형을 도로 높이로 평탄화(지형 정점 보정)하는 단계를 추가 |
| Overpass 공용 서버 호출 제한·타임아웃 | `raw/` 캐시 필수, 대형 영역은 타일별로 나눠 요청, 필요시 미러 서버 사용 |
| DEM 해상도가 낮아 지형이 뭉개짐 | 30m 데이터는 보간 후 약한 노이즈를 더해 평평함을 감춘다 |
| 모바일 발열·프레임 저하 | 저사양 모드 기본 적용(화면 폭 768px 이하) |

**라이선스**

- OSM 데이터는 ODbL이다. 화면에 “© OpenStreetMap contributors”를 표기하고, 가공한 `scene.json`을 공개할 경우 동일 라이선스 조건을 확인한다.
- DEM 출처별 이용 조건(상업적 이용, 출처 표기)을 착수 전에 확인한다.
- 실사 사진이나 지도 서비스 화면(카카오맵·네이버지도)은 검수 비교용으로만 보고, 텍스처나 데이터로 가져오지 않는다.
